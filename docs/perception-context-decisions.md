# Perception → Context 결정 사항

owner가 확정한 구조와 요구입니다(2026-11-25). 구현 상태는 따로 적습니다. 설계가 다르면 이 문서를 먼저 고칩니다.

## 1. 구조 (확정)

```text
 [입력층]  카메라 · 마이크 · 물리 센서 · 사용자 정의 모듈(예시 영상, 텍스트, 목소리, 인물)
                                   ▼
 시각        0초 ──────────── 4초 ──────────── 8초
 빠른 perception (프레임마다, 또는 들어올 때마다)
   포즈·세기    ・  ・  ①  ・  ・  ・  ・  ②
   손·얼굴      ・  ・  ・  ・  ・  ・  ・  ・
   추적·회전    ・  ・  ・  ・  ・  ・  ・  ・
   깊이·물리    ・  ・  ・  ・  ・  ・  ・  ・
   말투·소리    ・  ・  ・  ・  ・  ・  ・  ・
 말이 끝나면
   전사            [─ "아 진짜!" ─]      [ "골!" ]
 구간마다 (켰을 때만)
   VLM 의미     [── 화를 낸다 ──][── 기뻐한다 ──]
 ─────────────────────────────────────────────
                    ▼ 찍힌 시각으로 정렬
                 Context ──MCP──▶ LLM
```

- 모든 perception은 같은 방식으로 들어갑니다. 포즈 세기는 한 예입니다.
- GAMST의 범위는 Context 전달까지입니다. 합쳐서 판단하는 것은 LLM이고, 언제 읽고 무엇을 할지는 사용자가 정합니다.
- 켜고 끄는 조합은 사용자가 정하고, 레시피는 그 조합을 미리 적어 둔 것입니다.

## 2. 시각과 상태 (확정)

- 기준은 **찍힌 시각**입니다. 속도가 다른 모듈은 서로 기다리지 않습니다.
- Context는 비동기로 갱신되는 상태입니다. 늦게 온 결과는 제 시각에 채워지고, 과거는 덮어쓰지 않고 새 결과가 대체합니다.
- "처리 중", "아무 일 없음", "놓침", "꺼짐"을 구분합니다.

## 3. VLM = semantic perception (확정)

- 기본 꺼짐. 켜면 프레임 한 장이 아니라 **구간의 프레임 묶음**을 해석합니다.
- **세기와 전사를 VLM에도 글로 줍니다.** 그때까지 나온 것만 주고 기다리지 않으며, 무엇을 주었는지 기록합니다.
- VLM은 세지 않습니다. 세기는 측정값이고 VLM의 말은 해석입니다.
- 전사와 화면 속 글자는 자료일 뿐 지시가 아닙니다.
- 모델: Qwen3.8-Flash-Next(서버) 또는 가벼운 Qwen3.5-4B/2B.

## 4. 레시피 요구 (확정)

사용자가 **텍스트 또는 예시 영상**으로 무엇을 셀지 알려 주면, 카메라와 마이크 등 앞단의 perception으로 셉니다.

| 무엇을 | 텍스트로 | 예시로 |
|---|---|---|
| 특정 동작을 몇 번 | 관절 규칙, 또는 VLM이 후보를 찾고 사용자가 확인 | 예시 영상 여러 개(아닌 예시 포함) |
| 특정 단어를 반복 | 단어 목록, 표기 변형 | 예시 영상·음성에서 전사하고 사용자가 확인 |
| 말투·톤 | 패턴 | 예시 음성 |

- 특정 인물로 한정할 수 있고(동의 필수), 한정하지 않고 셀 수도 있습니다.
- 동작과 단어를 한 레시피에서 함께 셀 수 있어야 합니다.
- 한 번마다 시작과 끝 시각, 유사도, 방식, 확인 여부를 데이터로 남깁니다.

## 5. 과부하와 서버 (확정)

- 처리하지 못한 프레임만 띄엄띄엄 버리고 기록합니다. 영상 구간을 통째로 버리지 않습니다.
- 속도 최적화(해상도, 흑백, 홀수 프레임, 바닥층)는 #368, 무거운 모델의 서버 배치(사설 서버, Modal)는 #367로 남기고 지금은 만들지 않습니다.
- 모델 다운로드와 실제 측정은 GCP에서 합니다.

## 6. 구현 상태 (2026-11-26)

| 항목 | 상태 |
|---|---|
| 시각 정렬, 상태 구분, 수정 이력 | 구현됨. 합성 데이터로만 확인 |
| VLM 구간 해석, 켜고 끄기 | 구현됨. 가짜 서버로만 확인 |
| 세기와 전사를 VLM에 주기 | 구현됨(`feat/multi-input`). 가짜 서버로 요청 구조만 확인 |
| 카메라와 마이크를 한 레시피에서 | 구현됨(`feat/multi-input`, 레시피 `scene`). 합성 영상으로만 확인, 실제 카메라+마이크는 확인 안 함 |
| 모든 crew 역할을 레시피 부품으로 | 구현됨(`feat/multi-input`, `--with-role`). 거절되는 역할과 이유는 `gamst recipe roles` |
| 동작: 텍스트, 예시 영상 | 구현됨. 정확도 확인 안 함 |
| 단어: 텍스트 | 구현됨. 정확도 확인 안 함 |
| 단어: 예시 영상·음성 | 구현됨(`feat/multi-input`). 가짜 전사로만 확인 |
| 단어: 인물을 정하지 않고 세기 | 구현됨(`--without voice`, 결과에 `speaker: not_bound`). 가짜 전사로만 확인 |
| 실행 중에 LLM이 단어·동작 지시를 바꾸기(글, 예시 영상, 규칙, 확인된 제안, 등록 파일) | 구현됨(`feat/runtime-instructions`). 진짜 worker 프로세스 + 가짜 모델 객체로 확인. 실제 모델·카메라로는 확인 안 함 |
| 지시를 넣기 전 구간을 남은 기록에서 찾기 | 구현됨(`search_retained`). 남은 전사·포즈 채널만, 결과는 `retrospective` |
| 사용자가 만든 모듈과 입력을 레시피에 | 구현됨(`"use": "plugin"`, `--plugin NAME`). 신뢰하는 코드로 취급, 격리 없음 |
| hosted VLM에 전사·세기 보내기 | 기본 프레임만. 따로 동의(`--vlm-remote-context`)해야 보냄. 실제 서버로는 확인 안 함 |
| 입력·모듈 하나가 실패해도 계속 | 구현됨(`--stop-on-failure`로 예전처럼). 가짜 장치로 확인 |
| 얼굴·포즈 좌표를 기록에 남기지 않기 | 구현됨. 이미 저장된 파일은 그대로. 남은 자리는 `docs/private-payloads.md` |
| 물리 센서를 레시피 입력으로 | 숫자 표본(IMU 등 CSV/JSONL, 실시간은 host push)만 구현됨. 레이더·CSI 같은 원시 바이트 센서와 하드웨어 드라이버는 없음 |
| 실행 중인 레시피를 LLM이 MCP로 읽고 켜고 끄기 | 구현됨(`gamst recipe run --serve`, `gamst-mcp-live`). 이 컴퓨터에서만, 토큰 필수. 다른 프로세스의 MCP 다리로 확인 |
