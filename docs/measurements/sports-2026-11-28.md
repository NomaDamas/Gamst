# Sports M1 (racket): OpenTTGames on a GCP CPU VM, 2026-11-28

Measured with `scripts/sports_bench.py` on branch `feat/sports-recipes`. Every number below names its run; nothing here
was tuned on these clips (the recipes' defaults as committed).

What it says:

- Two clips agree: the sota stack's ball F1 0.84 / 0.88 and bounce F1 0.67 / 0.67; the detector-only stacks stay
  between 0.05 and 0.23.
- A general detector (COCO "sports ball") finds the table-tennis ball in about one labelled frame in ten; when it does,
  it is exact (1-2 px). The ball part decides the result: TrackNetV3 (trained on badminton, not table tennis) lifts
  ball recall from 0.10-0.12 to 0.79 and bounces from 3 to 19 of 28.
- The sota stack also reported 10 bounces that are not labelled bounces; whether some are labelled `net` events or
  hits has not been checked.
- Ultralytics' stack is the fastest on this CPU and the least accurate here; its page's "sub-5 ms" could not be
  reproduced as stated (no model or hardware named) and was not the question measured.

## Realtime (paced as the source's 120 fps), 30 s

| stack | start benchmark (1280x720) | chosen | frames processed / 3600 | ball F1 | bounces | run length / clip |
|---|---|---|---|---|---|---|
| roboflow | RF-DETR large 864.6 ms (1.2 fps) | rfdetr.nano | 174 (4.8 %) | 0.00 | 0 / 28 | 1.70x |
| ultralytics | YOLO26-m 230.4 ms (4.3 fps) | yolo26.s | 220 (6.1 %) | 0.003 | 0 / 28 | 1.42x |
| sota | RF-DETR large 705.1 ms (1.4 fps) | rfdetr.nano; TrackNetV3 lane 687 ms per frame | – | 0.008 | 0 / 28 | 2.77x |

Runs: `rt120-roboflow`, `rt120-ultralytics`, `rt120-sota` (the last one recorded: `rt120-sota-terminal.mp4`).

What it says: **on an 8-vCPU CPU VM none of the stacks keeps up with a 120 fps camera** (the input gives a frame every
8 ms; the fastest model needs about 230 ms). GAMST did what the design says: it measured, switched to the fallback,
said why, did not stop the input, declared every frame it could not process as a gap (`complete: false`, `lost`), and
never reported a count as complete. Realtime at this frame rate needs a GPU, which this free-trial account cannot use
(not checked further: GPU quota was not visible to the browser agent).
