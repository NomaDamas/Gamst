# Sports M1 (racket): OpenTTGames on a GCP CPU VM, 2026-11-28

Measured with `scripts/sports_bench.py` on branch `feat/sports-recipes`. Every number below names its run; nothing here
was tuned on these clips (the recipes' defaults as committed).

## Setup

| item | value |
|---|---|

What it says:

- Two clips agree: the sota stack's ball F1 0.84 / 0.88 and bounce F1 0.67 / 0.67; the detector-only stacks stay
  between 0.05 and 0.23.
- A general detector (COCO "sports ball") finds the table-tennis ball in about one labelled frame in ten; when it does,
  it is exact (1-2 px). The ball part decides the result: TrackNetV3 (trained on badminton, not table tennis) lifts
  ball recall from 0.10-0.12 to 0.79 and bounces from 3 to 19 of 28.
- The sota stack also reported 10 bounces that are not labelled bounces; whether some are labelled `net` events or
  hits has not been checked.
- Ultralytics' stack is the fastest on this CPU and the least accurate here; its page's "sub-5 ms" could not be
  reproduced as stated (no model or hardware named) and was not the question measured.

## Realtime (paced as the source's 120 fps), 30 s

| stack | start benchmark (1280x720) | chosen | frames processed / 3600 | ball F1 | bounces | run length / clip |
|---|---|---|---|---|---|---|
| roboflow | RF-DETR large 864.6 ms (1.2 fps) | rfdetr.nano | 174 (4.8 %) | 0.00 | 0 / 28 | 1.70x |
| ultralytics | YOLO26-m 230.4 ms (4.3 fps) | yolo26.s | 220 (6.1 %) | 0.003 | 0 / 28 | 1.42x |
| sota | RF-DETR large 705.1 ms (1.4 fps) | rfdetr.nano; TrackNetV3 lane 687 ms per frame | – | 0.008 | 0 / 28 | 2.77x |

Runs: `rt120-roboflow`, `rt120-ultralytics`, `rt120-sota` (the last one recorded: `rt120-sota-terminal.mp4`).

What it says: **on an 8-vCPU CPU VM none of the stacks keeps up with a 120 fps camera** (the input gives a frame every
8 ms; the fastest model needs about 230 ms). GAMST did what the design says: it measured, switched to the fallback,
said why, did not stop the input, declared every frame it could not process as a gap (`complete: false`, `lost`), and
never reported a count as complete. Realtime at this frame rate needs a GPU, which this free-trial account cannot use
(not checked further: GPU quota was not visible to the browser agent).

## The same on a GPU (GCP n1-standard-8 + NVIDIA T4, Spot)

The VM was moved to `n1-standard-8` with one T4 (driver 580, torch 2.8.0+cu128), same disk; models run with
`device: cuda`.

**Racket, OpenTTGames test_2, 30 s at 120 fps**

| run | result | processing / clip |
|---|---|---|
| sota, post (`gpu-post120-sota`) | ball F1 0.81 (0.86 / 0.76), median 10.5 px; bounces 14 / 28, 13 others found (F1 0.51, 4.9 ms) | 16.2x (CPU at 60 fps: 92.7x) |
| sota, realtime (`gpu-rt120-sota`, recorded) | RF-DETR large 55.3 ms -> nano; detector lane 51 ms and TrackNetV3 lane 78 ms per frame against 8 ms per input frame; ball model on 254 of 3600 frames; ball F1 0.05 | 1.20x |
| roboflow, realtime | RF-DETR large 53.7 ms -> nano; detector on 540 of 3600 frames; ball F1 0.003 | 1.16x |
| ultralytics, realtime | YOLO26-m 16.2 ms -> s; detector on 576 of 3600 frames; ball F1 0.005 | 1.15x |

Bounces at 120 fps (F1 0.51) are below 60 fps (0.67) with the same settings; the break detector compares `span` = 2
samples, half the time at 120 fps. Not investigated further and not tuned.

At 120 fps realtime stays out of reach on one T4: the models alone need 16-78 ms per frame, and even YOLO26-s processed
only about 19 frames per second, so something besides the model (decoding 1080p, moving frames to the worker) also
limits it (not measured separately).

## M3: team tracking, SportsMOT example (3 clips, 1280x720, 25 fps, CC BY-NC 4.0), T4

`team-field --stack S --timing T` per clip; the players module's tracks against `gt/gt.txt`, py-motmetrics at IoU 0.5
(`scripts/sports_mot_bench.py`). MOTA and IDF1 (HOTA, SportsMOT's own metric, needs TrackEval and was not computed;
the trackers' README HOTA numbers are with SportsMOT-trained YOLOX detections, here COCO detectors are untrained on it).

| clip | stack | post MOTA / IDF1 / ID switches | realtime MOTA / IDF1 / ID switches | realtime frames processed |
|---|---|---|---|---|
| football (c013, 875) | roboflow (RF-DETR L, ByteTrack) | **0.83 / 0.72** / 40 | 0.60 / 0.55 / 50 | 704 (nano) |
| | sota (RF-DETR L, BoT-SORT) | 0.80 / 0.67 / 56 | 0.58 / 0.55 / 51 | 723 (nano) |
| | ultralytics (YOLO26-x, its BoT-SORT) | 0.79 / 0.71 / 181 | 0.48 / 0.49 / 158 | 647 (YOLO26-m kept) |
| basketball (c009, 500) | roboflow | **0.62 / 0.52** / 29 | 0.51 / 0.34 / 43 | 481 |
| | sota | 0.58 / 0.53 / 28 | 0.43 / 0.34 / 43 | 481 |
| | ultralytics | 0.48 / 0.45 / 179 | 0.32 / 0.35 / 234 | 443 |
| volleyball (c016, 352) | roboflow | **0.35 / 0.55** / 15 | 0.26 / 0.47 / 15 | 352 |
| | sota | 0.30 / 0.49 / 18 | 0.22 / 0.38 / 18 | 352 |
| | ultralytics | 0.17 / 0.49 / 192 | 0.11 / 0.46 / 188 | 352 |

What it says:

- For player tracking the Roboflow combination (RF-DETR + ByteTrack) is the best of the three here, slightly ahead of
  GAMST's "sota" pick (BoT-SORT without ReID); the name "sota" is a choice to be revisited per recipe, not a measured
  ranking. Ultralytics' built-in tracker switches identities 6-10 times more often.
- Realtime at 25 fps on a T4 drops frames on the longer clips (RF-DETR large measured 55 ms, so nano was used; the
  pipeline as a whole, team split and tracker included, took about 2x the clip length even in post), and the scores
  drop accordingly; the runs say so (`complete: false`).
- Possession and passes are not labelled in SportsMOT and were not scored.
