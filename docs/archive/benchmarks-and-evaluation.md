# Benchmark and evaluation implementation archive

## Scope and evidence rules

This is an archive of the evaluation, replay, recording, transport and billing implementation at Gamst commit `5eb94c3bf841cd50cc8fd69ab3744eeede3b73fd`, on branch `feat/cleanup-eval-billing`. It covers all **65 files** under `benchmarks/` (64 Python modules and one JSON fixture) and all **15 SDK modules** slated for removal. Paths below are repository-relative so the archived identities remain precise after deletion.

A declaration, hash chain, synthetic fixture, loopback server, test double or successful software test is not a measured model-quality, real-latency or authentic-cost result. Each entry therefore separates its contract from results actually recorded in the repository. “No measured result recorded” means no real measured result for that entry was found in the source documentation or `docs/evidence/`; it does not assert that the code was never executed. The only numerical runtime result recorded for these Gamst benchmark modules is the explicitly synthetic workload in `docs/runtime-benchmark.md`, reproduced below. The two `docs/evidence/cross-repo-checksum-2026-11-{16,17}.json` files record repository HEAD/checksum bindings, not benchmark performance.

## 8. Recorded numerical result: synthetic SDK runtime only

`docs/runtime-benchmark.md` records CPython 3.12.3 on Linux x86_64 with eight logical CPUs, twenty warmup cycles and an in-memory SQLite store. These are real measurements **of a synthetic SDK workload**, not model quality, camera/microphone latency or long-run guarantees.

| Cycles / implementation | Text p50 / p95 | Signal p50 / p95 | State p50 / p95 | Wall | SQLite allocation | Peak process RSS |
|---|---|---|---|---|---|---|
| 200 / initial | 4.50 / 7.99 ms | 2.92 / 5.11 ms | 0.80 / 1.34 ms | 1.67 s | 8.82 MiB | 39.08 MiB |
| 500 / initial | 11.24 / 24.05 ms | 7.16 / 15.19 ms | 1.93 / 4.18 ms | 10.78 s | 47.85 MiB | 84.76 MiB |
| 500 / bounded evidence | 12.06 / 23.66 ms | 5.77 / 11.53 ms | 1.77 / 3.48 ms | 10.07 s | 8.32 MiB | 40.15 MiB |

The 200-cycle run retained 1,080 records and dropped 191 stalled-subscriber deliveries; each 500-cycle run retained 2,580 records and dropped 491. Bounding copied evidence reduced SQLite allocation by approximately 82.6% and peak process RSS by approximately 52.6% in the recorded 500-cycle comparison. The source JSON files were development-host `/tmp` artifacts and are not repository evidence. The same source explicitly says the eight-hour test had not been run and that retained numerical history/window queries still grow.

## 9. Documentation gaps and non-claims

- There is no recorded real held-out Gamst A/B/C quality/cost/p95 acceptance result for the archived evaluators. Most modules are validators, collectors or joins awaiting independently reviewed real inputs.
- Synthetic controller, transport, recording and financial fixtures establish contracts and arithmetic only. No authentic provider invoice, per-request allocation, complete whole-pipeline cost or genuine OpenAI call is recorded.
- The direct Responses client, native3/native4 readers and account aggregate importer do not verify provider execution, clock bucket assignment, account exclusivity or receipt authenticity.
- No real trained Smol/fill semantic-quality result, ORB-SLAM trajectory accuracy/real-device latency result, sustained realtime claim or eight-hour SDK soak is recorded for these entries.
- External Gamst-bench campaigns are separate evidence and must not be retroactively attributed to these synthetic modules. Their measured dev-subset and GAMST-HF results are indexed from the companion archive in Gamst-bench.
