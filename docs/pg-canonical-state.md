# Complete canonical PG state materialization

This is the strict-loading stage of #242, after the [original-source graph worker](pg-source-graph.md). It loads a complete **custom** canonical state into that concrete graph. It is not a converter for the released PG pickle, a generic caller-model adapter, a generation API, or a claim of trained/reference/physical acceptance. No actual PG canonical export or compatible historical runtime has been supplied during development.

The supervisor entry point is `await PGCanonicalProcess.open(python, graph, graph_sha, runtime_lock, runtime_lock_sha, canonical, canonical_sha, stage_root=..., startup_timeout=120)`. Import it from `humansense.pg_canonical_process`. Select an already-existing Python runtime. The worker must contain Gamst and the declared optional dependencies; nothing is installed or downloaded. Always `await owner.close()` after use. This delivery retains the loaded model privately in the owned worker and exposes a receipt and close, **not inference**. Native original PG generation/provider/Context follows in #242.

`stage_root` is an existing absolute directory separate from the source bundle (neither may contain the other). The supervisor creates its exclusive session directory and knows every allowed filename before spawning the worker. Its request file and immutable canonical snapshots are owned by that session. The worker never decides a cleanup root. One monotonic startup deadline covers process spawn and the remaining response wait, with no renewed allowance. A handle acquired after expiry is used only for cleanup, never admission. Exec failure also cleans the already-owned request directory. Startup timeout, caller cancellation, normal/concurrent close, late spawn completion and child failure all converge on verified child reap before deleting owned files. An unexpected entry is preserved and reported; caller/source directories are never recursively cleaned. The worker path is fixed, with no shell or caller-selected model factory.

## Canonical contract

The frozen canonical JSON has exactly `schema_version`, `format`, `graph_manifest_sha256`, `runtime_lock_sha256`, `graph_schema_sha256`, `graph_buffer_sha256`, `source_identity`, `export_provenance`, `tensors`, `shards`, and `budgets`.

- `schema_version` is 1 and `format` is `pg-reference-constructor-storage-v1`.
- `graph_schema_sha256` binds the actual constructed original graph's duplicate logical paths, shapes, alias identities, constructor/final dtypes and deterministic buffer digests, plus projection, graph-manifest and complete-runtime-lock hashes. It is **not** the older diagnostic rows-only hash. The loader computes this from the actual graph; callers cannot supply a substitute model/schema.
- `graph_buffer_sha256` exactly matches the original deterministic buffer digests. Nonpersistent buffers are preserved/regenerated and verified separately. Persistent position buffers, including this Q-Former's `position_ids`, must also match the original values after load.
- `source_identity` is the fixed PG publisher declaration `{pg_revision, pg_sha256, pg_bytes}`. `export_provenance` has `tool_revision` (40 lowercase hex), `source_evidence_sha256`, and `reference_replay_sha256`. These are caller declarations until independently verified; they do not prove that a custom export came from trained PG weights.
- `tensors` maps each actual graph representative to `{logical_names, shard, tensor_key}`. Sorted unique `logical_names` must cover exactly that original object-identity group. Every parameter/persistent-buffer path is covered once. Representative↔payload is a bijection. Equal-valued independent parameters remain independent; views, overlapping storage aliases and mixed persistent/nonpersistent groups are unsupported.
- `shards` is an ordered list of `{path, size, sha256}` with relative contained regular-file paths. The custom safetensors headers contain exactly the referenced tensors with `dtype`, `shape`, `data_offsets`; no extra metadata, unused entries, holes, overlaps or unaccounted bytes.

Canonical tensors contain values already stored in the **original constructor dtype after reference overlays/rounding, before CPU `.float()`**. F32, F16, BF16 and I64 are supported when the actual graph requires them. A BF16 canonical value widened to F32 retains the original rounding; arbitrary F32 values cannot substitute for BF16 constructor state. CUDA retains constructor dtype. The loader checks finite source and destination chunks, complete logical coverage, exact dtype/shape/device and real alias identities, with no missing/random/meta state. Only after all checks does it set `qformer_text_input=False`, eval and no-grad. It does not infer unknown base/PG overlay precedence or accept unsafe pickle fallback.

## Bounds and planned budgets

Canonical manifests are at most 4 MiB, with 20,000 logical paths/representatives and names up to 512 UTF-8 bytes. There are at most 64 shards, 64 GiB each and 128 GiB total. Headers are at most 4 MiB each and 16 MiB total, with at most 20,000 entries, tensor rank 8 and 2^35 elements. Exact actual-graph shapes take precedence over these maxima.

`budgets` contains exact nonnegative integer `disk_bytes`, `ram_destination_bytes`, `vram_destination_bytes`, and `ram_workspace_bytes`, each at most 512 GiB. Disk covers all snapshots **and the supervisor request** (reserve up to 8 MiB for that bounded request); free disk is checked as well. Destination allowance must cover actual unique graph storage at the requested target dtype before allocation. RAM workspace must allow at least 256 MiB for bounded headers/metadata/copy machinery. These are planned lower-bound admissions, not a guarantee of peak RSS/VRAM, mapped pages, native allocator behavior, graph-construction transients or later generation activations/KV.

Sources are streamed in at most 1 MiB blocks from checked descriptors into exclusive owned snapshots. Growth/truncation/replacement/hash mismatches fail. Snapshot files become read-only; the loader retains verified file descriptors and uses `pread`/`preadv`, never reopens mutable source paths for tensor data. Snapshot identity changes fail. This first route requires POSIX owned-descriptor support and little-endian state; it assumes a trusted immutable worker staging area, not protection from a hostile same-user writer restoring all metadata.

Conversion is serial: at most 262,144 elements and 1 MiB source data per unit, with one source buffer and bounded finite/copy work. No nonblocking CUDA queue is created; each copy and required device synchronization finishes before reuse. One destination tensor is allocated per original identity group and assigned to all its logical paths. The loader never builds a second complete materialized state dictionary. Header/schema/destination-budget rejection happens before destination allocation.

## Evidence and remaining gates

The `loaded` receipt means complete canonical state has been materialized in the owned graph, not that the export is trained or reference-compatible. `trained_identity_verified`, `reference_parity_verified`, and `runtime_compatibility_verified` remain false; `resource_admission` remains unavailable and `actual_acceptance` incomplete. A mismatched runtime returns unavailable before canonical loading. All errors stop startup; no inference handle is returned for partial state.

Tests use actual small safetensors bytes and real F16/BF16/I64 Torch tensors to verify widening/rounding, independent and shared aliases, persistent/nonpersistent buffers, missing state, dtype/finite failures, pre-allocation budget denial, FD identity/source mutation checks and actual owned-child lifecycle. Those fixtures validate mechanics only and do not stand in for a PG model. No trained weights, package installations or physical devices are used.

The remaining #242 work is original PG generation/eval preprocessing, prompt/output bounds and beam-score semantics, provider/Context lifecycle and actual canonical export/reference/resource/physical heldout acceptance. #105/#38 and the overall development Goal are not completed by this loading stage.
