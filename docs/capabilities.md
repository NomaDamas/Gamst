# GAMST 능력 정의 (2026-11-19 합의안)

> 아래 "합의 원문"은 2026-11-19 대화에서 사용자가 "토씨 하나 빼먹지 말고 문서화"하라고 승인한 제안을 그대로 옮긴 것입니다. 원문 아래의 "추가: 모달리티 조합"은 이후 사용자 요청("더 다양한 모달리티가 combination이 되면 좋겠다")에 따라 덧붙인 것으로, 원문과 구분해서 관리합니다.

## 합의 원문

네, 맞는 지적입니다. **GAMST가 무엇을 할 수 있는지 먼저 정하지 않고 벤치마크를 돌린 건 순서가 틀렸습니다.** 지금 실행은 채점만 남아서 곧 끝납니다. 끝나면 결과만 보존하고 VM은 바로 끄겠습니다. 이번 결과는 "감각 2개짜리 GAMST"의 기준선으로만 씁니다.

### GAMST의 기준 (한 줄)

> **싼 감각들이 쉬지 않고 보고 들으면서, 시간과 물리를 계산해 "사건"과 "확률"로 바꾸고, 그걸 기억한다.**

VLM은 사진을 띄엄띄엄 보고 그때그때 설명합니다. GAMST는 **흐름**을 봅니다. 그래서 VLM에는 없는 네 가지 무기가 생깁니다: **시간, 횟수, 확률, 기억**.

### Count 말고 "와우" 능력 3개

#### ① 확률 구름: 사용자가 걸어둔 규칙을 계속 계산

말씀하신 아이디어 그대로입니다. 사용자가 이렇게 규칙을 겁니다.

> "아이가 가스레인지 1m 안에 들어가고 + 물 끓는 소리가 나면 위험"

GAMST는 이렇게 계산합니다.
- 아이 위치를 추적합니다 (검출 + 추적 모델).
- 가스레인지에 가까울수록 위험 확률이 **올라갑니다**.
- 끓는 소리(오디오 이벤트 모델)가 들리면 한 번 더 **올라갑니다**.
- 아이가 멀어지면 시간이 지나며 **식습니다** (지수 감쇠).
- 문턱을 넘으면 알림을 보내고, 충분히 내려가야 해제됩니다 (히스테리시스). 그래서 경보가 깜빡거리지 않습니다.

**수학:** 근거가 쌓이는 베이즈 누적 + 시간 감쇠 + 위치 추적(칼만 필터)

**와우 장면:** 화면 위에 위험 **구름**이 아이를 따라 움직입니다. 물이 끓으면 진해지고, 아이가 거실로 가면 옅어집니다. VLM은 "지금 아이가 부엌에 있다"까지만 말할 수 있습니다. **위험이 쌓였다가 풀리는 흐름**은 GAMST만 보여줄 수 있습니다.

#### ② 순간 포착 + 물리 측정: "정확히 언제, 얼마나"

소리와 움직임의 시각을 ms 단위로 맞춰서 **물리량**을 계산합니다.

| 장면 | GAMST가 계산하는 것 | 물리 |
|---|---|---|
| 점프 | 발이 떨어진 순간 → 착지 순간 = 체공 시간 0.52초 → **점프 높이 33cm** | h = g·t²/8 |
| 번개 | 번쩍한 뒤 2.9초 후 천둥 → **거리 약 1km** | 거리 = 343m/s × Δt |
| 공 던지기 | 프레임 위치 변화 → **시속 82km**, 착지 예측 | 등가속도 운동 |
| 컵이 테이블 끝으로 미끄러짐 | **0.4초 뒤 떨어짐**을 떨어지기 전에 예측 | 속도 + 남은 거리 |
| 유리 깨짐 | 깨지는 소리 onset과 충돌 프레임을 맞춰 **결정적 1장** 저장 | 오디오·영상 시각 정렬 |

**와우 장면:** 카메라 하나로 "점프 33cm, 체공 0.52초"가 바로 나옵니다. 결정적 순간 사진도 자동으로 뽑힙니다. 1~2FPS로 보는 VLM에는 원리적으로 불가능합니다.

#### ③ 리듬과 주기: "보이지 않는 떨림을 본다"

화면의 아주 작은 밝기·움직임 변화를 주파수(FFT)로 분석합니다.

| 대상 | 결과 | 필요한 FPS |
|---|---|---|
| 자는 사람 가슴 | **호흡수 14회/분** (0.2~0.5Hz) | 낮아도 됨 |
| 얼굴 피부색 | **심박 72bpm** (rPPG, 1~2Hz) | 15fps 이상 |
| 손 떨림 | **5.2Hz 떨림** (파킨슨 범위 4~6Hz) | 12fps 이상 |
| 기계·선풍기 | **회전수, 진동 이상** | 회전 속도에 따라 다름 |
| 동전 (Halo) | **12바퀴** | 60~240fps |

**와우 장면:** 카메라만 비추고 있는데 "호흡 14회/분, 심박 72"가 나옵니다. 사람 눈으로는 안 보이는 신호입니다.

#### (공통 기반) 기억

①②③이 만든 사건이 전부 **시각 + 근거와 함께 상태 기록**에 쌓입니다. 그래서 이런 질문에 답할 수 있습니다.
- "열쇠 어디 뒀지?" → "14:02:11에 현관 선반, 그 뒤로 안 움직임"
- "오늘 아이가 가스레인지에 몇 번 갔어? 제일 위험했던 순간은?" → 확률 그래프 + 그 순간 사진
- 영상을 지워도 이 기록은 남습니다. 개인정보 측면에서도 장점입니다.

### Halo 제품으로 이어보면

| 제품 | 쓰는 능력 | 한 줄 |
|---|---|---|
| **Halo Home** | 확률 구름 + 기억 | 아이·노인·반려동물 위험 구름, "아까 뭐 했어?" |
| **Halo Fit** | Count + 물리 | 반복수, 템포, 점프 높이, 체공 시간 (폰 하나로) |
| **Halo Care** | 리듬 | 자는 동안 호흡수, 낙상 순간 포착 |
| **Halo Kitchen** | 확률 구름 + 순간 포착 | 끓어넘침 예측, 불 켜놓고 자리 비움 경고 |
| **Halo Factory** | Count + 확률 구름 | 사이클 타임 카운트, 위험구역 침입 확률, 기계 진동 이상 |
| **Halo Play** | Count + 물리 | 동전 회전 수, 주사위 결과, 공 속도 (데모·SNS용) |

### 다음 순서 제안

1. **지금 실행:** 채점이 끝나면 결과를 보존하고 **VM을 즉시 정지**합니다.
2. **"GAMST 능력 정의서" 작성:** 위 4개 능력(Count, 확률 구름, 순간 포착·물리, 리듬)을 각각 정리합니다. 입력 / light model / 수식 / 출력 사건 / MCP로 물을 수 있는 질문.
3. **능력마다 작은 실제 데이터 검증:**
   - Count: RepCount
   - 물리: 점프 영상 (체공 시간 → 높이를 실측과 비교)
   - 리듬: 공개 rPPG 데이터셋 (예: UBFC, 라이선스 확인 필요)
   - 확률 구름: 직접 촬영한 부엌 시나리오
4. 그다음에 벤치마크를 돌립니다.

어느 능력부터 만들지 정해 주시면 됩니다. 제 추천은 **② 순간 포착·물리(점프 높이)**입니다. 데모가 제일 직관적이고, 폰 영상 하나로 바로 검증할 수 있습니다.

## 추가: 모달리티 조합 (사용자 요청으로 덧붙임)

원칙은 같습니다. 감각이 하나일 때는 "변했다"까지지만, **서로 다른 감각의 시각을 맞추면 물리량과 확신이 생깁니다.** 모든 조합은 같은 시계(monotonic clock)로 정렬된 GAMST 신호로 상태 기록에 들어갑니다.

| 조합 | 계산하는 것 | 물리·수학 | 능력 |
|---|---|---|---|
| 영상 + 오디오 | 번개–천둥 거리, 유리 깨짐 결정적 1장, 박수·발소리 템포 | 343m/s × Δt, onset 정렬 | ② |
| 오디오 단독 | 공 튕김 소리 간격 → **반발계수**와 낙하 높이 | e = √(t₂/t₁), h = g·t²/8 | ② |
| 영상 + 폰 IMU | 점프 체공 시간 교차검증 (가속도 ≈ 0g 구간), 낙상 충격 크기 | 자유낙하, 충격 g | ②③ |
| 영상 + 오디오 + IMU | 동전·팽이 회전: 영상 주기 + 회전 소리 주파수 상승 | 주기 추정, 소리 주파수 변화 | Count ③ |
| 스테레오 마이크 | 소리가 난 **방향** | 도달 시간차(TDOA) | ① |
| 영상 + 환경 센서 (온도·조도·근접) | 확률 구름의 추가 근거 (예: 화구 온도 상승) | 베이즈 근거 결합 | ① |
| 화면 OCR + 음성 | 점수판 숫자 변화와 해설 발화의 순서 | 사건 순서·인과 | 기억 |
| 영상(rPPG) + 마이크(호흡음) | 심박·호흡을 두 경로로 측정해 신뢰도 상승 | 주파수 일치 검사 | ③ |

검증도 같은 원칙을 따릅니다. 실제 촬영 또는 공개 실데이터만 쓰고, 정답은 실측값(줄자, 스톱워치, 센서 기록) 또는 사람 라벨로 둡니다. 합성 데이터는 쓰지 않습니다.
