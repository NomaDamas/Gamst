# PG original-source graph/schema worker

This is the concrete architecture step after the [artifact prerequisite](pg-artifact-preflight.md), toward issue #242. It constructs the original graph only when an explicitly supplied compatible runtime and local source/config/tokenizer assets exist. It does not load trained tensors, generate an answer, register a provider, or claim PG native compatibility. #242, #105 and #38 remain open.

```
python -m humansense.pg_graph --manifest /absolute/manifest.json --sha256 CANONICAL_SHA256
```

Run this as a dedicated local worker. The frozen manifest is the same strict declaration used by `pg_artifact`; the CLI compares installed dependency metadata before importing ML. A mismatch returns `status=unavailable` without opening model assets or importing torch, transformers, accelerate, timm or LAVIS. Matching metadata is only an admission check, not proof of compatibility. The current development runtime mismatches the historical candidate; actual full-graph execution has **not** been validated.

Before actual graph construction, supply `--runtime-lock /absolute/lock.json --runtime-sha256 CANONICAL_LOCK_SHA256`. Without it the worker returns unavailable. The lock has exactly `{schema_version: 1, python, platform, machine, packages}`; `packages` maps normalized lowercase/hyphen distribution names to exact versions for **every installed distribution in that isolated worker**, including transitive dependencies. Duplicate installed identities, missing/extra packages or platform differences fail closed. Maximum 1,024 distributions and 256 KiB JSON. This is an immutable operator-supplied deployment lock, not an automatic install plan. Matching distribution metadata does not verify binary integrity or tested compatibility. Do not reuse a lock from a different worker.

The graph uses exactly authenticated original sources from the declared historical LAVIS candidate. `pg_graph.FILES`, `CLASSES`, `METHODS`, `FUNCTIONS`, `IMPORTS` and `ASSIGNS` define the versioned projection. Each entire original file is SHA-verified before any source execution; unknown revisions fail. Private namespaces have an import allowlist and never load the installed/global `lavis` package. There is no generic caller model/factory interface.

The projection retains original graph methods and constructor behavior. It omits outer training/checkpoint download APIs and registry decorators. EVA retains the original factory's architecture assignment and precision conversion while omitting its asset-loading middle section. Private BERT/T5 factories use supplied local config/tokenizer assets and the original architecture classes, never `from_pretrained` weight acquisition. The original pure-PyTorch T5 layer normalization is selected explicitly; optional Apex probing and the global layer-normalization registry mutation are omitted. The original TensorFlow conversion helper is retained solely because the original class binds it; its local conversion imports are outside the allowlist and fail closed if called. It is not an exported conversion API. These are declared adaptations, not claims of an unchanged full LAVIS import process. Original supplied files retain their complete BSD/Apache notices; the declared LAVIS license is also verified. Do not redistribute extracted upstream code without the original notices.

The architecture config identities are deliberately fixed and bounded:

- BERT: `google-bert/bert-base-uncased`, revision `86b5e0934494bd15c9632b12f734a8a67f723594`, config SHA256 `7160e1553ad2ca51d8c1cb066be533db31826e12d173824c1bb0cb1a4f187d20` (570 bytes).
- T5: `google/flan-t5-xxl`, revision `ae7c9136adc7555eeccc78cdd960dfd60fb346ce`, config SHA256 `dd923bd687781f336e7845b7e011b7bbeca5fdde5c27f8b06071540340707dbd` (674 bytes).

These are currently published config identities, **not PG-author-pinned dependencies**. The BERT manifest origin remains the upstream constructor alias `bert-base-uncased`. Each config role contains one file. Tokenizer files must be declared, SHA/size verified, and share an otherwise empty role directory. `local_files_only=True` prevents a tokenizer download. The worker additionally rejects loader file redirects/custom-loader settings in bounded (64 KiB) strict configuration JSON, limits filenames to the supported BERT/T5 role names, and passes the authenticated vocabulary/fast-tokenizer paths explicitly. Absolute and relative `vocab_file`, `tokenizer_file` and other file overrides cannot escape the declared inventory; local-only mode alone would not prevent that. As in the prerequisite, this assumes an immutable trusted bundle; snapshot checks cannot protect later reads against a hostile writer.

Construction preserves `qformer_text_input=True`, all word/position embeddings and text FFN modules. The output records the intended later execution flag False but does not switch it or perform inference. Original `T5.tie_weights()` restores graph-defined shared encoder/decoder embeddings after parameter registration interception; the untied language head remains separate.

`accelerate.init_empty_weights(include_buffers=False)` keeps parameters meta while retaining small deterministic buffers and EVA's CPU `linspace(...).item()` calculation. It changes parameter registration process-wide, which is why this entry point belongs in a dedicated worker. It may still allocate transient CPU tensors before registration; no peak-memory or resource-admission guarantee is made. The default torch floating dtype must be float32 and the default device CPU before construction; modified caller defaults fail closed. No dependency installation is automatic.

The schema enumerates duplicate parameter/buffer paths, graph identity aliases, persistent/nonpersistent state, original constructor dtype, final CPU/CUDA dtype and deterministic buffer digests. It reports unique constructor/final CPU storage separately, **not** peak memory. Schema coverage is not trained checkpoint coverage. All readiness, compatibility, trained-state and actual acceptance flags remain false/unavailable; even successful schema construction returns `status=unavailable`, reason `schema_only_no_canonical_state`.

The later loader must preserve the full dtype chain: EVA selectively fp16 and T5 bf16 receive reference checkpoint values **before** the final CPU `.float()`. Direct F32-to-final-F32 loading would skip reference rounding. It must validate full canonical keys/shapes/dtypes, finite values after narrowing, original alias consistency and every materialized parameter/persistent buffer, with no missing/random/meta state. Unique schema storage alone cannot authorize loading: conversion/materialization workspace, activations, peak CPU/VRAM and lifecycle require separate budgets and actual measurements. Unknown legacy overlay composition remains unsupported.

The next steps remain strict canonical state loading, original PG `generate.py` plus bounded eval preprocessing, sequence-score semantics, provider/Context lifecycle, and actual trained/reference/physical heldout acceptance. No cheap/realtime claim follows from this schema worker.

Validation uses actual pinned source AST compilation and source-body preservation checks, an isolated runtime-mismatch CLI, import-escape checks, declared tokenizer scope/hash tests and tiny tensor inventory tests. Tiny tensor fixtures test machinery only; they do not stand in for the actual PG graph or model. Set `GAMST_PG_SOURCE_ROOT` to an existing original source directory to run the source-only test; tests never download sources or weights.
